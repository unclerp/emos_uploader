# 配置来源

常规业务配置以 `config.ini` 为准。网页配置管理中的处理配置、手动规则、字幕组映射等入口编辑 INI；`delete_after_upload`、`upload_targets` 和 `max_upload_workers` 不再提供数据库编辑入口。

LLM 提供商保持原行为：优先读取数据库中的启用记录，没有可用记录时回退到 INI 的 `llm_provider_N`。网页保留 LLM 提供商的数据库编辑入口；`llm_fallback` 总开关等仍在 INI 中设置。

历史数据库中的手动规则、字幕组映射和运行时配置保留，不删除、不覆盖。相关旧配置 API 返回 HTTP 409，避免缓存的旧网页继续写入无效副本。首次启动不再将这些重复配置导入数据库；LLM 提供商和登录账号的初始化保持可用。账号、API Key、任务历史功能继续使用数据库。

## 保存后自动应用

网页保存 INI 或 LLM 数据库配置后自动校验、构建组件并切换运行版本。“重新加载”按钮从 INI 重新读取并执行同样的应用流程。无需重启容器。

新任务使用新版本；开始处理的视频、目录整理、网盘整理和流式 HTTP 响应持有原版本，完成后才释放旧客户端。队列和去重记录跨版本共享。已排队但尚未开始的任务使用开始处理时的版本。

新下载器初始化或连接检查失败时，旧运行版本继续工作。网页区分“保存成功”和“应用成功”，并显示当前版本、旧版本的使用者数量、等待时间及清理失败。保存失败配置后，可修正并保存，或再次点击“重新加载”重试。历史配置数据不因此被删除。

回收站清理的新旧版本共用执行锁，禁止同时执行；热更新不会重新触发仅用于进程启动的 run_on_start/catch_up_on_start。更换 emya 数据库连接时使用独立连接池，不影响正在执行的旧任务。

业务配置支持热更新；Docker 的端口映射、挂载和镜像不属于网页业务配置。首次加载这版程序仍需一次代码部署，之后的业务配置保存无需重启。
